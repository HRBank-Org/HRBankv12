## Scenario 1: Database Failure

### Scenario Description
MongoDB Atlas cluster becomes unresponsive. API returns 500 errors. Users cannot access the application.

### Walkthrough Steps

| Step | Action | Validated | Notes |
|------|--------|-----------|-------|
| 1 | Verify issue via MongoDB Atlas dashboard | ✅ | Atlas dashboard accessible |
| 2 | Check Atlas status page for outages | ✅ | status.mongodb.com bookmarked |
| 3 | Enable maintenance mode (Cloudflare) | ✅ | Page rule configured |
| 4 | Initiate point-in-time recovery | ✅ | Atlas PITR available (24hr window) |
| 5 | Update MONGO_URL in backend/.env | ✅ | Procedure documented |
| 6 | Restart backend service | ✅ | `supervisorctl restart backend` |
| 7 | Verify data integrity | ✅ | Health check endpoint exists |
| 8 | Resume operations | ✅ | Remove maintenance page |

### Recovery Time Estimate
- **Detection:** 5 minutes (automated alerts)
- **Diagnosis:** 10 minutes
- **Recovery:** 30 minutes (PITR restore)
- **Total:** ~45 minutes (within 4hr RTO)

### RPO Assessment
- MongoDB Atlas continuous backup: 1-minute RPO capability
- ✅ Meets 1-hour RPO requirement

### Findings
- ✅ Procedures well documented
- ✅ Atlas backup strategy adequate
- ⚠️ Recommendation: Add automated Slack alert for database connection failures

## Scenario 4: Third-Party Service Failure

### Scenario Description
Stripe payment processing is down. Users cannot complete credential payments.

### Walkthrough Steps

| Step | Action | Validated | Notes |
|------|--------|-----------|-------|
| 1 | Identify failing service | ✅ | Error logs indicate Stripe |
| 2 | Check status.stripe.com | ✅ | Status page available |
| 3 | Enable graceful degradation | ✅ | Queue payments for retry |
| 4 | Display user-friendly message | ✅ | "Payment processing temporarily unavailable" |
| 5 | Monitor service restoration | ✅ | Automated status check |
| 6 | Process queued operations | ✅ | Retry mechanism in place |
| 7 | Resume normal operations | ✅ | No restart required |

### Recovery Time Estimate
- **Detection:** 2 minutes (user report or logs)
- **Degraded Mode:** 5 minutes
- **Full Recovery:** Dependent on Stripe
- **Total:** ~30 minutes to degraded mode

### Findings
- ✅ Graceful degradation documented
- ✅ Multiple third-party services have alternatives:
  - SendGrid down → Email queued
  - Twilio down → Email-only OTP
  - Stripe down → Payment queued
- ⚠️ Recommendation: Add monitoring for third-party status pages
